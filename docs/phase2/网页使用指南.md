# 网页使用指南

这个网页有两个主要用途：用公开轴承实测数据检查算法能否识别故障部位；用虚拟电动工具生成多传感器波形，理解工况、损伤与处理流程。它目前没有连接你的真实电钻。

## 1. Windows 打开方法

1. 下载完整项目 ZIP，右键选择“全部解压”，进入解压后的项目文件夹。不要直接在压缩包里运行。
2. 安装 Python 3.12，安装时勾选 Python Launcher；项目已有 Python 环境时可以直接使用。
3. 双击根目录的 **启动实验平台.bat**。首次启动会安装依赖并校验数据与模型，期间保留命令窗口。
4. 浏览器打开 **http://localhost:8501**。停止时回到命令窗口按 Ctrl+C。

项目已带处理好的公开数据和训练模型，普通查看不需要自己重新下载或训练。如果在云工作区使用，在项目根目录执行 `python -m streamlit run app.py --server.address 0.0.0.0`，再使用工作区提供的端口预览打开 8501；运行命令本身不会自动获得公网网址。

## 2. 第一页：公开轴承预验证

这是默认首页，输入来自凯斯西储大学 CWRU 的驱动端振动通道。模型只判断四类：正常、内圈故障、滚动体故障、外圈故障。

| 页面区域 | 干什么 | 你怎么操作 |
| --- | --- | --- |
| 测试集记录 | 选择一段没有参与训练的历史记录 | 初次保留默认即可，也可换另一条 |
| 记录内窗口 | 每次查看一个 1,024 点振动窗口 | 填入从 1 开始的窗口编号 |
| 开始分析当前窗口 | 对当前窗口运行诊断模型 | 点击一次，等待“已完成” |
| 下一窗口并分析 | 查看同一记录的下一个窗口 | 手动点击，逐窗比较结果 |
| 重置 | 清除判断，回到第一个窗口 | 想重新查看时点击 |
| 测试状态 | 当前窗口是否完成分析 | 看“待分析 / 已完成 / 模型未就绪 / 失败”及完整状态说明 |
| 模型判断 | 算法给出的故障部位 | 与右侧真实标签比较 |
| 数据集真实标签 | 实验记录中已经知道的故障类别 | 它是对照答案，不是算法输出 |
| 已知缺陷尺寸 | 数据集人工加工缺陷的尺寸 | 小、中、大尺寸档来自该尺寸，不代表自然轻、中、重度磨损 |

下方有三个区域：

- **输入波形与频谱**：左边是去均值、小波阈值处理后的振动，横轴为窗口内相对时间；右边是 FFT，横轴为 Hz。它们是两种看同一个信号的方法。
- **预处理与特征**：中文说明 RMS、峭度、峰值、能量占比等特征及其作用。神经网络实际使用去噪波形，特征表用于分析和传统算法对照。完整原始字段放在折叠区。
- **下载与追溯**：可下载直接训练的 NPZ、当前窗口 CSV、全部特征与标签、数据划分说明及原始来源校验清单。训练 NPZ 包含 `X`、`y`、`split`、`record_id` 等字段。

类别分数还没有做概率校准，不能把“90% 分数”解释为现场故障概率。当前留出的正常记录误判较多，首页会明确提示误判情况；这次预验证没有达到可直接用于真实运维告警的程度。CWRU 没有自然退化寿命标签，因此本页不显示健康百分比或真实剩余寿命。

## 3. 第二页：虚拟电动工具实验台

左侧切换到此页后，可以选择电钻、角磨机或冲击扳手。设置损伤等级、负载比例、转速、记录时长、环境温度和随机种子，点击 **生成虚拟实验记录**。

建议先做两组比较：保持工具、转速、负载和种子不变，只改变正常/轻度/中度/重度；然后保持损伤设定不变，改变负载或转速。这样可以区分“损伤影响”与“工况影响”。这些只是生成模型的现象，不是已经证明的真实工具规律。

| 下方区域 | 怎么看 |
| --- | --- |
| 振动 | m/s² 的虚拟波形、频谱，默认 25,600 Hz 采样 |
| 电流 | A 的虚拟波形、频谱，默认 25,600 Hz 采样 |
| 温度 | ℃ 的虚拟趋势，默认 10 Hz 采样；几秒记录温升很小属于正常情况 |
| 特征与导出 | 以中文名称和单位展示特征，可下载本次波形 NPZ、配置 JSON、特征 CSV |

**“设定损伤等级”是你输入的生成条件，不是模型诊断结果。** 改动控件后要再次点击生成，页面中间显示的才会更新。相同配置和随机种子能够复现同一记录。

温度变化斜率为 ℃/秒，“本次记录温升”为末值减首值。电流一、二、三阶幅值以模拟轴转频为基准，不代表市电谐波或已校准 THD。虚拟波形不直接喂给 CWRU 单通道模型，也不直接喂给旧版六维模型，避免通道、单位和时间尺度不匹配。

## 4. 第三页：模型与使用说明

这个页面解释输入怎样变成判断，并列出轻量 CNN、标准 Transformer、线性注意力的公开数据实验结果、参数量和 CPU 耗时。准确率按百分比展示；宏平均 F1 同时考虑各类别，接近 1 表示更好。

原来的六维仿真模型确实包含 Transformer 和 LSTM，共 17,789 参数。新的公开波形模型通过卷积提取局部信息，比较有无注意力及线性注意力。线性注意力降低理论上随 token 数平方增长的部分，但不保证小窗口在 CPU 上更快；以表中的实测耗时为准。CPU 耗时不是 MCU 部署结果。

NASA IMS 区域显示四个轴承通道的历史 RMS 趋势，默认查看轴承 1。横轴是首条记录起的壁钟时间差，不是已确认的有效运行时长。下载表里的 `endpoint_proxy_rul_hours` 只是到数据集最后记录的代理倒计时，不是模型预测或精确故障时刻。最后两次快照各通道都出现低幅值，可能是停机或工况变化，不能解释为维修成功。

## 5. 旧版告警和维修工单在哪里

旧版已保留在 `legacy_app.py`，仍使用原来的六维特征仿真与虚拟寿命标签。Windows 在项目终端执行：

```powershell
.\.venv\Scripts\python.exe -m streamlit run legacy_app.py --server.port 8502
```

然后打开 http://localhost:8502，按“生成仿真 → 保存分析记录 → 告警 → 工单 → 维修记录 → 模拟复测”体验运维闭环。它的健康、寿命和复测结果仍然是仿真，不是公开轴承实验的验证结果。

## 6. 常见情况

| 情况 | 处理 |
| --- | --- |
| 网页打不开 | 检查启动命令窗口是否仍开着；确认浏览器地址和端口正确 |
| “模型未就绪”或数据校验失败 | 重新下载完整项目；需要自行重建时执行 `python scripts/prepare_public_data.py` 与 `python scripts/train_bearing.py --epochs 15` |
| 判断与真实标签不同 | 这是实际误判，应记录窗口和记录 ID 用于分析；不要改真实标签来迁就模型 |
| 为什么没有剩余寿命 | 当前公开分类模型没有可验证的自然退化寿命预测能力 |
| 想证明任务书指标 | 仍需真实工具多工况采集、跨设备验证、寿命试验、传感器异常与独立维修复测、目标硬件耗时测量 |
