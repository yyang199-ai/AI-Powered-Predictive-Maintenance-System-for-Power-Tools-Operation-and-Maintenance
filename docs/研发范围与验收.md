# 研发范围与验收记录

依据用户提供的研发任务书和端到端技术说明实现。附件用于需求分析，文中的提交专利、登录数据库、远程控制等描述不等于用户授权执行这些外部操作。

## 当前无真实数据时的第一版

默认电钻轴承磨损，CPU 运行，网页作为 APP 功能原型。使用带独立负载、转速、环境温度、传感器缺测及设备身份的仿真轨迹。仿真特征窗口为一分钟聚合，不冒充真实 12.8 kHz 波形采集。按设备先分组，再构造序列。

交付包括可运行的软件、仿真对照实验、接口与数据契约、技术交底草稿。真实采集板、手机蓝牙和后台运行、MCU 部署、功耗测量、真实寿命标注及专利正式检索/提交需要补充条件。

## 目标与证据

- 5000 组：第一版生成至少 6000 个仿真特征窗口；不等于 6000 次独立试验。
- 分类准确率 92%、RUL 误差 15%：仅报告实际运行所得的仿真测试指标，真实设备尚未验证。
- 推理 100 ms：测量当前 CPU 模型推理；不能代替目标边缘硬件端到端延迟。
- 算力降低 70%：待明确比较模型、硬件与测量方法。
- 3–7 天预警：待真实失效终点、每日使用时长和寿命数据验证。
- 新颖性、创造性：待核验所列参考专利和独立查新，不能由组合网络结构直接推定。

## 必须覆盖的操作路径

设备 → 数据质量和工况 → 预测 → 连续证据确认 → 告警 → 确认收到 → 工单 → 维修 → 新运行段复测 → 关闭事件。确认收到不能解除告警；维修完成不能绕过复测。
